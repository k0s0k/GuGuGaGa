# 知识库导入格式

CodeRecall 2 使用 UTF-8 JSON 交换知识点。一个文件包含一个知识库和 1–1000 个知识点；导入前会进行格式校验。下载 [可直接导入的模板](../public/knowledge-template.json) 或查看 [JSON Schema](../public/knowledge-schema.json)。桌面发行目录也附带这两个文件。

```json
{
  "format": "coderecall.knowledge",
  "version": 1,
  "deck": { "title": "我的学习笔记", "description": "按主题归纳" },
  "items": [
    {
      "title": "一个可独立回答的问题",
      "kind": "qa",
      "prompt": "要主动回忆的内容是什么？",
      "answer": "清楚、准确、可核对的答案。支持 **Markdown**。",
      "tags": ["主题"],
      "source": "笔记文件名 / 章节"
    }
  ]
}
```

`format` 必须是 `coderecall.knowledge`，`version` 必须是整数 `1`。这个格式版本描述知识点交换协议，与应用版本 2.0.0、完整备份版本 2 相互独立。

## 字段

| 对象 | 字段 | 必填 | 限制与含义 |
| --- | --- | --- | --- |
| deck | title | 是 | 知识库名称，1–200 字，不能全为空白 |
| deck | description | 否 | 描述，最多 5000 字；省略时为空 |
| deck | id | 否 | 稳定标识，用于识别重复导入 |
| item | title | 是 | 知识点标题，1–300 字 |
| item | kind | 是 | `qa`、`cloze` 或 `procedure` |
| item | prompt | 是 | 提问或练习任务，1–100000 字，支持 Markdown |
| item | answer | 是 | 答案或步骤，1–100000 字，支持 Markdown |
| item | tags | 否 | 最多 30 个标签，每个 1–60 字；重复标签合并 |
| item | source | 否 | 来源说明，最多 2000 字；可以写文档名、章节或 URL |
| item | id | 否 | 知识点稳定标识，同一个导入文件内不能重复 |

所有文本都不能含空字符。必填文本会去掉两端空白。`id` 为 1–100 位字母、数字、下划线、点、冒号或短横线，并以字母或数字开头。文件不能添加表外字段，不能包含 JSON 注释、`NaN` 或 `Infinity`。规范化后的内容上限为 8 MiB；HTTP 请求也有 8 MiB 上限，接近边界时请分批导入。应用最多保存 500 个知识库与 10000 个知识点。

JSON Schema 便于编辑器预先检查结构；总字节数、跨条目的重复 ID 和已有库冲突仍由应用校验。最终以应用校验结果为准。

## 三种卡片

- `qa`：提出一个具体问题，先回忆，再揭晓答案。
- `cloze`：问题里至少包含一个 `{{c1::答案}}`。编号为正整数，可包含多个标记，例如 `{{c2::另一个答案}}`；每个标记的答案不能包含换行或花括号。仍然需要填写独立的 `answer` 字段。复习时先隐藏空缺，揭晓后核对。
- `procedure`：提出一个实践任务，在答案里用 Markdown 有序列表写出可执行、可核对的步骤，适合 Blender、UE5、工具使用或实验流程。

填空标记仅用于复习时遮挡答案，并不自动判断输入或分别调度每一个空。三种卡片都以整个知识点为单位记录四档记忆反馈。

## 重复导入与编辑

没有填写 ID 时，应用根据规范化内容生成稳定 ID。原文件再次导入不会新增相同卡片，也不会清空已有复习记录。同一 ID 对应的内容不同会阻止整批导入；修改现有卡片应使用编辑功能，或为确实不同的新内容指定新 ID。

新建自己的知识库时，请删除模板中的 `deck.id` 和各 `item.id`，或为它们指定新的值。不要把改过内容的示例继续作为原示例 ID 导入。

**知识库导入与设置中的完整备份导入不同**：知识文件合并学习内容；完整备份包含学习记录、笔记、题解、设置等，会替换当前状态并先备份。知识库内容文件不携带进度，也不包含 API 密钥。
