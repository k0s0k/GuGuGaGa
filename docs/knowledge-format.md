# 知识库导入格式

GuGuGaGa 使用 UTF-8 JSON 交换知识点。一个文件包含一个知识库和 1–1000 个知识点；导入前会进行格式校验。下载 [可直接导入的模板](../public/knowledge-template.json) 或查看 [JSON Schema](../public/knowledge-schema.json)。桌面发行目录也附带这两个文件。

```json
{
  "format": "coderecall.knowledge",
  "version": 1,
  "deck": { "title": "我的学习笔记", "description": "按主题归纳" },
  "items": [
    {
      "title": "一个可独立回答的问题",
      "kind": "qa",
      "prompt": "要主动回忆的内容是什么？",
      "answer": "清楚、准确、可核对的答案。支持 **Markdown**。",
      "tags": ["主题"],
      "source": "笔记文件名 / 章节"
    }
  ]
}
```

`format` 固定为 `coderecall.knowledge`，`version` 固定为整数 `1`。该版本描述知识点交换协议，与应用版本、完整备份版本独立。

## 字段

| 对象 | 字段 | 必填 | 限制与含义 |
| --- | --- | --- | --- |
| deck | title | 是 | 知识库名称，1–200 字，包含有效文本 |
| deck | description | 否 | 描述，最多 5000 字；省略时为空 |
| deck | id | 否 | 稳定标识，用于识别重复导入 |
| item | title | 是 | 知识点标题，1–300 字 |
| item | kind | 是 | `qa`、`cloze` 或 `procedure` |
| item | prompt | 是 | 提问或练习任务，1–100000 字，支持 Markdown |
| item | answer | 是 | 答案或步骤，1–100000 字，支持 Markdown |
| item | tags | 否 | 最多 30 个标签，每个 1–60 字；重复标签合并 |
| item | source | 否 | 来源说明，最多 2000 字；可以写文档名、章节或 URL |
| item | id | 否 | 知识点稳定标识，在文件内唯一 |

文本使用有效字符，标题等简短字段自动整理两端空白，提问与答案保留 Markdown 排版。`id` 长度为 1–100 位，以字母或数字开头，可包含字母、数字、下划线、点、冒号或短横线。文件使用上述字段和标准 JSON 语法。规范化内容与 HTTP 请求上限均为 8 MiB，较大的文件请分批导入。应用最多保存 500 个知识库与 10000 个知识点。

JSON Schema 用于编辑器预检，应用还会校验总大小、ID 唯一性及已有内容冲突。

## 三种卡片

- `qa`：提出一个具体问题，先回忆，再揭晓答案。
- `cloze`：问题里至少包含一个 `{{c1::答案}}`。编号为正整数，支持多个标记，如 `{{c2::另一个答案}}`；标记答案使用单行普通文本，同时填写独立的 `answer` 字段。复习时先隐藏空缺，揭晓后核对。
- `procedure`：提出一个实践任务，在答案里用 Markdown 有序列表写出可执行、可核对的步骤，适合 Blender、UE5、工具使用或实验流程。

三种卡片都以整个知识点为单位记录四档记忆反馈，由用户核对回忆结果。

## 重复导入与编辑

省略 ID 时，应用根据规范化内容生成稳定 ID。相同文件重复导入会复用已有卡片并保留复习记录。相同 ID 出现内容冲突时，整批导入会提示错误；现有卡片请在应用中编辑，新内容可使用新 ID。

基于模板新建自己的知识库时，请省略 `deck.id` 和各 `item.id`，或为它们指定新的值。

**知识库文件用于合并学习内容；完整备份用于恢复个人数据。** 完整备份包含学习记录、笔记、题解和设置，导入前会保存当前数据，再替换当前状态。
