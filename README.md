# GuGuGaGa · 每天一点，把知识记牢

本地优先的通用知识复习与打卡工具：为 C++、英语、Blender、UE5 等学习主题建立自己的知识库，把笔记拆成可主动回忆的问答、填空或操作流程，再用间隔重复安排复习。同时保留完整 **Python 3 / C++17、LeetCode / ACM 双模式的 Hot100** 专区。

界面采用浅色留白、侧边栏、分栏工作台与深色主题，借鉴 Codex 桌面版的界面组织方式。可双击 Windows `.exe` 打开独立窗口，也可通过源码启动本地网页应用。日常使用、知识库管理和按标题拆分笔记无需账号或 API；使用可选的 AI 拆分时才连接用户指定的模型服务。

## 2.1 新增功能

- **新名称与图标**：应用更名为 GuGuGaGa，桌面窗口、任务栏、快捷方式和网页使用统一的新名称与企鹅图标。
- **个人头像**：可在偏好设置上传自己的图片，并在工作空间显示；头像随本地数据和完整备份保存。
- **工作空间布局**：修复侧边栏底部工作空间被遮挡的问题，小窗口也能访问导航与个人信息。
- **直接沿用进度**：2.1 延续 CodeRecall 2 的数据目录、备份格式和草稿，不需要手动搬迁。

## 2.0 功能

- **自己的题解**：按题目、语言与答题模式保存简洁版、注释版和完整解析；可修改、复制到答题区，也可恢复内置参考答案。个人版本独立存储，原始题解保留。
- **统一代码编辑行为**：四空格缩进；Enter 换行并按语法缩进；Tab 优先接受补全，无补全时缩进；Shift+Tab 反缩进；Ctrl+Space 主动触发补全。Enter 不再误接受候选项。
- **Markdown 笔记**：支持标题、列表、任务列表、表格、引用、链接和代码块，可编辑与预览。原始 HTML 不执行，外部图片显示说明文本。
- **通用知识库**：创建、编辑、搜索与分类自己的知识点，支持问答、填空和实践步骤；先回忆、再揭晓，用四档反馈安排复习，可收藏或归档。
- **笔记转知识点**：导入 Markdown / TXT、粘贴文本，按标题本地拆分，或调用兼容 Chat Completions 的大语言模型 API；结果先预览、编辑、校验，再确认导入。
- **统一学习进度**：知识点与算法题共同计入每日完成数量、打卡和日历；两种学习内容分别保留复习进度。
- **通用学习模式**：在偏好设置关闭「每日计划包含 Hot100」，就只推荐自己的知识库内容；内置算法题库与历史记录仍保留。
- **开放导入协议**：[JSON 模板](public/knowledge-template.json)、[JSON Schema](public/knowledge-schema.json)、[格式说明](docs/knowledge-format.md) 与 [AI 拆分说明](docs/document-import.md) 随项目提供，可使用其他模型生成符合格式的文件。

原有 Hot100 版本已保存为 Git 标签 **`v1.0.0`**，并上传到 [私有 GitHub 仓库](https://github.com/k0s0k/CodeRecall)。本机旧版桌面程序另存于 `release/CodeRecall-v1.0.0`，源码压缩包为 `release/CodeRecall-v1.0.0-source.zip`。

## Hot100 专区

- **100 道 Hot100 题目**：中文题意、约束、样例、原题链接；按数组、链表、哈希、树、图、回溯、动态规划、二分等专题组织，支持搜索、难度和学习状态筛选、收藏。
- **今日计划**：优先列出到期复习，再推荐未学习题目；默认每日目标 3 题、新题 3 题，避免第一次使用就缺少可完成的计划内容。
- **四档记忆反馈**：「忘记了 / 有点模糊 / 记住了 / 很熟练」决定下次复习。忘记后 10 分钟重学，其他反馈按天安排；到期时间精确到时刻。
- **自动打卡与日历**：当天完成的不同题目达到目标即打卡。同一题多次复习保留记录，但当天完成数量只计一次；可查看月历、某天记录、学习时长与连续打卡。
- **两种语言 × 两种模式**：LeetCode 模式补全函数或类；ACM 模式编写完整标准输入输出程序。每题提供适配的初始代码、输入说明和样例输入。
- **每题一套参考算法、三层答案**：简洁代码、带中文注释的代码、完整解析；两种语言对应同一思路，解析包含步骤、正确性说明、复杂度与易错点。
- **本地代码运行**：运行内置样例或自定义输入，显示输出、耗时和错误；C++ 有可用编译器时编译后运行。
- **本地持久化**：SQLite 保存题目进度、反馈、笔记、收藏和四种语言/模式各自的代码草稿。支持 JSON 导入导出，导入前自动备份当前数据。

## Windows 桌面版

新版桌面包的入口是 **`release/GuGuGaGa-v2.1.0/GuGuGaGa.exe`**，双击即可启动。应用自带 Python 运行环境、C++ 编译工具和已构建的界面，使用桌面包不需要另行安装 Node.js、Python 或 C++ 编译器。

请把 **`GuGuGaGa.exe` 与同目录的整个 `_internal` 文件夹一起保留**。移动、复制或备份程序时，操作整个 `release/GuGuGaGa-v2.1.0` 文件夹；只复制 `.exe` 到桌面会导致依赖缺失。日常使用可以把程序放在固定目录，再创建桌面快捷方式。

在 `.exe` 所在目录双击 **`create-shortcut.cmd`**，即可创建 **GuGuGaGa** 桌面快捷方式。旧版 CodeRecall 快捷方式保留；同名快捷方式指向其他位置时，会改用 `GuGuGaGa (2)` 等名称，不覆盖已有快捷方式。程序所在文件夹移动后，可以重新运行脚本。

GuGuGaGa 2.1 直接沿用 CodeRecall 2.0 的 **`%LOCALAPPDATA%\CodeRecall-v2\coderecall.db`** 和 WebView 草稿缓存。两者共享数据与单实例启动协议，升级无需迁移；使用新版本前请先退出正在运行的 CodeRecall 2。名称变化不会清空原有学习进度。最初的 CodeRecall 1.0 仍使用 **`%LOCALAPPDATA%\CodeRecall\coderecall.db`**，其记录与 2.x 独立。数据与程序分开存放，移动程序目录不会删除学习记录；跨电脑迁移时可在设置页导出、导入完整 JSON 备份。

首次启动且新版尚无数据库时，优先采用同项目的新版源码数据库，其次复制旧版桌面数据或旧版源码数据，再在副本中升级结构。迁移使用 SQLite 一致性备份，包含已经提交但仍在 WAL 中的数据；**保留原数据库，不覆盖新版已有进度**。程序升级前也会写出备份。若无法自动找到原数据，可从旧版导出 JSON，再在新版设置页导入。

原生窗口使用 Windows WebView2。系统缺少可用 WebView2 时，启动器会打开浏览器界面并保留一个小控制窗口，方便重新打开界面或退出本地服务。桌面包启动过程中无需运行开发终端；下方源码启动与开发环境说明仅适用于直接运行项目源码。

## 快速启动

### 环境

| 组件 | 用途 | 要求 |
| --- | --- | --- |
| Python | 后端、Python 代码运行 | Python 3.10 或更高，加入 PATH |
| Node.js + npm | 安装与构建前端 | 推荐 Node.js 22 或更高；构建完成后日常运行不需要 Node |
| g++ / clang++ | C++17 编译与运行 | 可选；需支持 `-std=c++17` |
| 浏览器 | 使用界面 | 当前版本的 Edge / Chrome / Firefox |

Python 后端只使用标准库，无需 `pip install`。第一次安装前端依赖需要联网；构建完成后题库、题解、记忆调度和本地运行可离线使用。打开外部原题链接仍需联网。

### Windows 一键启动

双击项目根目录的 **`start.cmd`**，或者在 PowerShell 中执行：

```powershell
.\start.ps1
```

如果系统执行策略阻止脚本，请使用 `start.cmd`，它只为这次进程传入执行策略参数，不修改系统全局策略。

脚本会检查 Python；前端尚未构建或源文件较新时，安装缺失的依赖并构建。已有可用构建时直接运行，已有依赖时不会每次重新安装。服务留在当前终端，不会弹出额外后台窗口。

看到服务地址后，打开 **[http://127.0.0.1:8766](http://127.0.0.1:8766)**。保持终端运行，按 **Ctrl+C** 停止服务。关闭网页不会删除进度。

可选参数：

```powershell
# 强制重新构建前端
.\start.ps1 -Rebuild

# 使用另一个端口或另一个数据文件
.\start.ps1 -Port 8877 -Data ".local\my-progress.db"
```

### 手动启动

在项目根目录依次执行：

```powershell
npm install
npm run build
python -m server.app
```

然后打开 **[http://127.0.0.1:8766](http://127.0.0.1:8766)**。如果 `python` 不在 PATH、但安装了 Windows Python Launcher，可将命令中的 `python` 换成 `py -3`。

服务默认只监听 `127.0.0.1`，支持本机的 `127.0.0.1` 与 `localhost` 访问。不要把开发服务直接暴露到公网或反向代理到公开域名。

## 每天怎么用

通用学习可以先创建知识库与知识点，或从 [模板](public/knowledge-template.json) 导入。也可以将 Markdown / TXT 笔记拆分成预览卡片，调整后保存。复习时先在心里回答或实际完成操作，再揭晓答案，按真实回忆程度选择反馈。知识点与 Hot100 题目共同计入当天目标，在日历中查看学习记录。归档的知识点保留历史记录并退出日常复习。

Hot100 的日常流程：

1. 打开「今日计划」，先完成已到期的复习，再做推荐新题。也可以从题库按专题自由选择。
2. 选择 Python 或 C++，再选择 LeetCode 或 ACM 模式，尝试独立写出实现。
3. 运行样例，必要时使用自定义输入。卡住时先看思路，再查看注释版；复习时可用简洁版核对。
4. 根据自己能否独立回忆思路与实现提交记忆反馈。运行通过与记忆掌握分别判断；不要仅因为读懂答案就选「很熟练」。
5. 达到当天不同题目数量目标后自动打卡，在日历中回看学习记录。

初次使用建议保留 **目标 3 题 / 新题 3 题 / 保留率 90%**。积累到期复习后，可把新题降到 1–2 题，给复习留时间；打卡目标也可以按实际时间调整。减少每日目标时，当天已有学习达到新目标会立即打卡。已获得的打卡不会因之后提高目标而撤销。

设置更高的目标保留率会缩短之后的复习间隔，不会追溯重排已有到期时间。当天多次学习同一题只贡献一个完成名额，但每次记忆反馈都会更新复习计划。重复发送同一个学习事件不会重复计数。

## 复习模型与时间规则

调度是本项目编写的透明启发式模型，借鉴间隔重复与遗忘曲线理念，**不是墨墨背单词专有调度算法，也未宣称复现其效果**。

- 以稳定性 `S` 表示预计记忆保留率降到 90% 所需天数，展示的估计值为 `R(t) = 0.9^(t/S)`。
- 首次选择「有点模糊 / 记住了 / 很熟练」时，初始稳定性分别为 0.5 / 1 / 4 天；90% 目标下，最早按 1 / 1 / 4 天安排。
- 之后按反馈、当前稳定性与预估遗忘程度调整。选择「忘记了」降低稳定性，并安排 **10 分钟后**重学。
- 按天的间隔至少 1 天、至多 365 天；稳定性封顶 365 天。该估计帮助安排练习，不是对个人真实记忆准确率的测量。

复习时间使用带时区的 ISO 时间，并统一按 UTC 计算；日历和打卡使用**运行后端的电脑本地日期**。浏览器传来的日期最多允许相差一天以容忍跨日或时区差异，实际记录仍归本机当天；相差更大时会提示检查系统时间。没有任意补打卡接口。

## LeetCode / ACM 模式

**LeetCode 模式**：只编写题目要求的 `Solution` 方法，设计题编写相应类。运行器提供标准节点类型与输入输出适配。

**ACM 模式**：代码包含完整入口，读取标准输入并输出一行 JSON 结果。每题页面提供准确的输入协议及可直接粘贴的示例；数组、矩阵、树等使用明确的长度或行列信息，设计类题也有对应操作序列格式。

本地样例是学习辅助，不是 LeetCode 官方评测服务。样例通过只表示通过当前显示的用例；自定义输入只运行并展示结果，不自动判断正确性。参考答案与评测适配涵盖集合顺序、多种合法树形等情况，仍建议在原题页面提交验证更多边界。

程序在你的本机以当前账户权限执行。运行器设有执行时间、输出大小和并发数量限制，**不是不可信代码的安全沙箱**；不要粘贴运行不信任的程序。应用不自动登录 LeetCode，也不代替你向原站提交代码。

### 配置 C++

设置页显示当前 Python 版本与 C++ 编译器可用状态。没有编译器时，C++ 题解、编辑和代码导出仍可使用，点击运行会明确提示环境尚未配置。

Windows 可以使用项目提供的便携工具链脚本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-cpp.ps1
```

脚本从 [w64devkit 官方发行页](https://github.com/skeeto/w64devkit/releases) 下载固定版本、检查 SHA-256，再解压到 **`.local/toolchains/w64devkit`**；不会修改系统 PATH、注册表或全局设置。已安装时会直接显示现有编译器。应用会自动检测这个项目内的 g++，完成后重新启动后端并刷新网页即可。

本次交付机器的运行环境为 **Python 3.11.13 / GCC 16.2.0**。便携工具链属于本地运行文件，不随 Git 源码提交；换电脑时请重新运行配置脚本或使用现有编译器。

安装支持 C++17 的 g++ 或 clang++ 后，加入 PATH 并重新打开终端；也可在启动前指定现有编译器的完整路径：

```powershell
# 将示例路径替换为你实际安装的编译器路径
$env:CODERECALL_CXX = "C:\msys64\ucrt64\bin\g++.exe"
python -m server.app
```

`CODERECALL_CXX` 只填写可执行文件路径，不附带参数。程序使用 `-std=c++17 -O2`；不直接适配 MSVC 的 `cl.exe`。编译器依赖的运行库也应能被当前环境找到。

## 进度、备份与迁移

源码运行默认数据库为 **`.local/coderecall-v2.db`**。初次启动若发现旧 `.local/coderecall.db`，会复制到新版位置并保留原文件。桌面版使用上文的用户目录。数据库包含进度、笔记、草稿、个人题解、知识库、收藏、设置、学习事件和打卡日期，默认不上传到远端。

在设置页「导出备份」下载版本 2 完整 JSON；换电脑时启动另一份应用，再从设置页导入。也可导入旧版版本 1 备份，新字段自动补为空。**新版备份不能导回旧版应用**。导入会替换当前状态，界面要求确认；服务端先校验内容，再把原数据写到数据库所在目录的 `before-import-时间-标识.json`。验证失败或备份写入失败时，当前数据库保持不变。

知识文件使用另一种 `coderecall.knowledge` 格式，只合并卡片内容，具体规则见 [知识库导入格式](docs/knowledge-format.md)。如需迁移个人题解、复习进度和笔记，请使用设置页的完整备份。

误导入后，可以把对应 `before-import-*.json` 再导入恢复。备份文件不会自动删除；需要时可自行整理。数据库写入使用 SQLite 事务，并在读取待更新状态前取得写锁，防止同时保存笔记、草稿或反馈时丢失更新。

如需更换存储位置：

```powershell
python -m server.app --data "D:\GuGuGaGaData\progress.db"
```

## 开发与测试

使用原版源码时可从 `v1.0.0` 标签导出到其他目录，避免把当前开发目录切换回旧版而覆盖正在修改的文件。`.local`、`release`、`node_modules` 与生成的 `dist` 不提交到 Git；私有仓库保存源代码与构建说明，不包含个人学习数据库或 API 密钥。

在两个终端分别启动后端和 Vite：

```powershell
# 终端 1：后端，负责题库、进度和运行代码
python -m server.app
```

```powershell
# 终端 2：前端热更新
npm install
npm run dev -- --port 5173 --strictPort
```

开发界面为 **[http://127.0.0.1:5173](http://127.0.0.1:5173)**，Vite 将 `/api` 代理到 **8766**。服务端访问校验允许本机后端端口及开发端口 5173；若 5173 被占用，先停止占用程序，不要让 Vite 自动换到未经配置的端口。仅启动 `npm run dev` 而未启动 Python 后端会导致接口请求失败。

```powershell
# TypeScript 校验及生产构建
npm run build

# Python 单元测试及本地接口测试
python -m unittest discover -s tests -v

# 100 题 × 两种语言 × 两种答题模式，回归注释版参考答案
python scripts/verify_content.py

# 同时检查简洁版与注释版；需要可用的 C++ 编译器
python scripts/verify_content.py --styles brief annotated

# 按语言或题号检查，便于修改某题后复测
python scripts/verify_content.py --languages python --ids 4 94 208
```

调度测试覆盖首次反馈、10 分钟重学、时区等价、保留率与间隔边界；数据测试覆盖事件幂等、不同题目计数、日期容错、备份恢复、无效导入回滚以及多线程/多 Store 实例并发；HTTP 测试覆盖本机 Host、Origin、会话令牌与 JSON 格式检查。

Windows 桌面构建：

```powershell
# 首次先准备便携 C++ 工具链；前端依赖用 npm ci 安装
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-cpp.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-desktop.ps1
```

构建脚本在 `.local/package-env` 安装锁定版本的桌面依赖，下载并校验嵌入式 Python，再生成 `release/GuGuGaGa-v2.1.0`。`-SkipInstall` 可复用已有打包依赖，`-SkipFrontend` 可复用已构建的前端。旧 `release/CodeRecall`、`release/CodeRecall-v1.0.0` 与 `release/CodeRecall-v2.0.0` 不作为构建输出。发行包附带操作说明、导入模板与第三方许可证信息。

`verify_content.py` 通过应用实际使用的本地运行器验证题库，默认最多同时运行 2 个程序，报告写入 **`.local/content-verification.json`**。任何失败都会返回非零退出码；`--report` 可指定报告路径。全量 C++ 编译需要一些时间；回归期间建议不要同时在界面运行代码，以免占满本地并发名额。

## 常见问题

**打开 8766 提示前端尚未构建**：运行 `npm install`、`npm run build`，或使用 `start.cmd`。

**页面无法连接后端**：确认 Python 终端仍在运行，地址使用 `127.0.0.1` 或 `localhost`，端口与终端输出一致。开发模式需要同时运行两个终端。

**提示会话失效**：后端重启会更新会话令牌，刷新网页即可。不要用旧网页继续提交。

**端口被占用**：停止旧服务，或执行 `python -m server.app --port 8877` 并打开对应地址。Vite 开发代理默认仍指向 8766。

**更新代码后界面没有变化**：重新运行 `npm run build`，刷新网页；`start.ps1 -Rebuild` 也可强制构建。

**JSON 导入被拒绝**：先区分知识库内容与完整备份。知识库入口接受 `coderecall.knowledge` 格式；设置页接受本应用导出的版本 1 或 2 备份。错误信息会指出不合法的数据。请保留原文件，避免直接编辑唯一备份。

**AI 拆分失败**：检查服务是否兼容 Chat Completions、模型名称及密钥是否有效。长文档请分批处理；也可先用本地标题拆分。AI 失败不会导入半成品。
